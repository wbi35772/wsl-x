
```text

```

## 6. 订阅刷新

`mihomo-refresh.timer` 已 **disabled**（2026-10-29 起）。当前节点表来自最后一次手动刷新，重启后仍在配置文件中，但不会自动更新。

手动刷新：

```bash
cd ~/infra/net/mihomo
sudo -u mihomo ./bin/refresh-providers
```

脚本行为（`bin/refresh-providers`，2690 B）：

1. 从 Sub-Store 拉取 5 个 provider；
2. 调 `sanitize-provider` 修双重编码与控制字符；
3. 写回 `config/providers/`；
4. 失败时**不覆盖**旧文件；
5. 成功后 `PUT /configs?force=true` 热加载。

`sanitize-provider`（1388 B）专门处理 latin1/utf8 双重编码、BOM、控制字符导致的 YAML 解析失败。

## 7. 故障处置

### DNS 全挂

```bash
# 1. 看 mihomo 是否活着
sudo systemctl status mihomo --no-pager

# 2. 临时恢复 DNS（绕过 mihomo）
sudo chattr -i /etc/resolv.conf
echo 'nameserver 172.30.192.1' | sudo tee /etc/resolv.conf
sudo chattr +i /etc/resolv.conf

# 3. 修好 mihomo 后改回
sudo chattr -i /etc/resolv.conf
echo 'nameserver 127.0.0.1' | sudo tee /etc/resolv.conf
sudo chattr +i /etc/resolv.conf
```

### 出口不通

```bash
~/infra/net/emergency/probe.sh
```

检查三件事：

| 通道 | 地址 | 用途 |
|---|---|---|
| A | `127.0.0.1:7890` | WSL 自身走 mihomo |
| B | `172.30.192.1:10810` | 借 Windows 侧代理出口 |
| C | `http://<WSL-IP>:7890` | 反向给 Windows 用（需 allow-lan） |

### Docker 容器不能上网

确认 `docker-tun-bypass` 规则在：

```bash
ip rule show | grep 172.17
# 期望：100: from 172.17.0.0/16 lookup main
```

缺失时：

```bash
sudo systemctl restart docker-tun-bypass
```

### 多发行版共享 IP

WSL2 是「一个 VM 装多个发行版」，不是一发行版一 VM：

| 测试 | 结果 |
|---|---|
| x01 `eth0` | `172.30.196.173/20` |
| 临时 x02 `eth0` | 同一地址 |
| x02 访问 `localhost:3005` | 拿到 x01 的 Forgejo |
| x02 监听 3005 | `bind: Address already in use` |

结论：端口必须全局唯一；`wsl.x01` / `wsl.x02` 只是同一地址的两个别名。
