## 2. 端口隔离改造（2026-11-01）

> 全文（含 TUN、多发行版、wslpp、附录）见 [历史/WSL网络与端口隔离.md](历史/WSL网络与端口隔离.md)；本节只保留结论。

### 问题

NAT 模式下 `localhostForwarding=true` 会让 `wslrelay.exe` 把 WSL 的监听端口镜像到 Windows。结果是：

- Windows 的 `127.0.0.1:3005` 能打开 Forgejo，但 Windows 自己也监听 3005；
- 端口空间混乱，Windows 本地服务与 WSL 服务互相抢占；
- 排查时无法判断请求到底进了哪一侧。

### 处置

```ini
# C:\Users\24999\.wslconfig
[wsl2]
localhostForwarding=false
```

备份：`.wslconfig.bak-20261101_015318`。执行 `wsl --shutdown` 后生效。

### 结果

| 检查 | 结果 |
|---|---|
| `wslrelay.exe` | 不再出现 |
| Windows `127.0.0.1:3005` | 不通（预期） |
| `wsl.x01:3005` | 通，200 |
| Windows 侧 3005 / 8787 监听 | 0 个 |

## 3. 「容器反复重启」的结论

### 现象

- `docker ps` 里容器 uptime 只有几十秒；
- `docker inspect` 的 `StartedAt` 不断刷新；
- `docker.service` 长时间 `activating`；
- Postgres 每次都 `rejecting connections` 几分钟。

### 根因

不是容器崩溃，是 **WSL VM 被反复关机再冷启动**：

1. 默认 `vmIdleTimeout` 约 60 秒；
2. 每次没有活动的 `wsl.exe` 会话，VM 就整体关机；
3. 下一次命令重新冷启动，dockerd 重建 sandbox、所有容器重启；
4. 冷启动本身要 3–4 分钟，看起来像「无限重启」。

### 修复

```ini
# C:\Users\24999\.wslconfig
vmIdleTimeout=86400000   # 24 小时
```

实测：空闲 240 秒后 VM uptime 仍连续，问题消失。

### 仍需知道的冷启动开销

| 阶段 | 时间 |
|---|---|
| VM → systemd | 秒级 |
| mihomo 可用 | 秒级 |
| dockerd 稳定 | 3–4 分钟 |
| Postgres 崩溃恢复 | 约 4 分钟 |
| Forgejo 可用 | 1–2 分钟 |

## 4. 故障速查

### 4.1 Windows 打不开 WSL 服务

```powershell
# 1. 确认 IP
wsl -d Ubuntu-24.04 -u dev -- hostname -I

# 2. 同步 hosts
D:\Network\小工具\port\wslip.cmd

# 3. 用 wsl.x01，不要用 127.0.0.1
curl http://wsl.x01:3005/
```

### 4.2 域名解析失败

```bash
sudo systemctl status mihomo --no-pager
# 应急：
sudo chattr -i /etc/resolv.conf
echo 'nameserver 172.30.192.1' | sudo tee /etc/resolv.conf
sudo chattr +i /etc/resolv.conf
```

### 4.3 Docker 容器没网

```bash
ip rule show | grep 172.17
# 期望 100: from 172.17.0.0/16 lookup main
sudo systemctl restart docker-tun-bypass
```

### 4.4 Postgres 一直 rejecting

```bash
docker logs --tail 40 x01-data-postgres
docker exec x01-data-postgres pg_isready
```

崩溃恢复期间正常拒绝连接，等 3–5 分钟；若日志出现数据页错误再介入。

### 4.5 Forgejo 502

```bash
docker ps --filter name=x01-dev-forgejo
docker logs --tail 50 x01-dev-forgejo-db
```

MySQL 未 healthy 时 Forgejo 会 502；先等 MySQL，再看 Forgejo。

### 4.6 端口被占

```bash
sudo ss -lntp | grep :8081
```

常见冲突：clash-proxy-demo 漏 `DASHBOARD_PORT=8085` → 回落 8081 → 撞 mitmweb 后退出。

### 4.7 goofish 分析失败

```bash
docker logs --tail 100 goofish-hardware-sniper
curl -s http://127.0.0.1:8086/health
```

检查顺序：

1. AI 端点（InstaCloud warp 域名）是否可解析；
2. `OPENAI_BASE_URL_FALLBACK` 是否可用；
3. 是否触发免费模型限流（并发必须为 1）；
4. 任务是否被 FailureGuard 暂停（24 小时）。

### 4.8 订阅节点不更新

`mihomo-refresh.timer` 已 disabled，属预期。手动：

```bash
cd ~/infra/net/mihomo && sudo -u mihomo ./bin/refresh-providers
```
