## 4. `C:\Users\24999\.wslconfig`

```ini
[wsl2]
memory=12GB
processors=8
swap=4GB
swapFile=D:\\WSL2\\Ubuntu-24.04\\swap.vhdx
vmIdleTimeout=86400000
networkingMode=nat
dnsTunneling=false
autoProxy=false
firewall=false
localhostForwarding=false

[experimental]
autoMemoryReclaim=gradual
sparseVhd=true
```

要点：

| 键 | 作用 | 注意 |
|---|---|---|
| `swapFile` | swap 与系统盘同放 D 盘 | 必须双反斜杠，单反斜杠会报「行 5 无效」 |
| `vmIdleTimeout=86400000` | VM 空闲 24 小时才关 | 默认 60 秒，太短会让容器反复冷启动 |
| `localhostForwarding=false` | 关闭 WSL→Windows 的 localhost 端口镜像 | Windows 侧改用 `wsl.x01` |
| `networkingMode=nat` | NAT 模式，WSL 独立 IP | 所有发行版共享同一 VM 与 IP |
| `firewall=false` | 关闭 Hyper-V 防火墙 | 与 NAT 搭配 |
| `sparseVhd=true` | vhdx 稀疏 | 删除文件后不会自动立即缩小，需 `wsl --manage --set-sparse` 或 diskpart 压缩 |

备份：`C:\Users\24999\.wslconfig.bak-20261101_015318`（关闭端口镜像前的版本）。

## 5. `/etc/wsl.conf`

```ini
[boot]
command = ip link set dev eth0 mtu 1400
systemd=true

[user]
default=dev

[interop]
enabled=true
appendWindowsPath=true

[automount]
enabled=true
options="metadata,umask=22,fmask=11"

[network]
generateResolvConf = false
hostname = X01
```

| 项 | 作用 |
|---|---|
| `mtu 1400` | 规避部分线路的 PMTU 黑洞 |
| `systemd=true` | 用 systemd 管理 mihomo / Docker |
| `generateResolvConf=false` | 保留自定义 DNS（指向 mihomo） |
| `automount options` | `/mnt/c`、`/mnt/d` 带 metadata，文件权限可区分 |

## 6. DNS

`/etc/resolv.conf`：

```text
nameserver 127.0.0.1
options edns0
```

`127.0.0.1:53` 是 mihomo 的 DNS 监听。**mihomo 未启动时域名解析全部失败**，但 IP 直连不受影响。应急改法见 `02-网络层与端口.md` 第 7 节。

## 9. 启动链与时间预期

```text
Windows 开机
  └─ WSL VM（vmIdleTimeout 24h）
      └─ systemd
          ├─ mihomo-uidrule（oneshot，先加 ip rule）
          ├─ mihomo（always，3s 重启）
          ├─ containerd
          └─ docker（notify）
              └─ 8 个 unless-stopped 容器
```

| 场景 | 预期 |
|---|---|
| 冷启动后 dockerd 可用 | 约 30–60 秒 |
| dockerd 完全稳定（清陈旧 sandbox） | 约 3–4 分钟 |
| Postgres 非正常关机后恢复 | 约 4 分钟（fsync），期间 `rejecting connections` |
| Forgejo 首次可用 | 依赖 MySQL healthy，约 1–2 分钟 |

> 这是 WSL + Docker 的正常冷启动开销，不是故障。详见 `07-历史与故障处置.md`。
